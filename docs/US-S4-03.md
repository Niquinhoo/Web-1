# US-S4-03 — API REST de categorías

**Código:** `#main-s4-us3`  
**Estado:** Completada  
**Estimación:** 2 horas  
**Tiempo real:** 30 minutos  

## Objetivo

Administrar categorías desde el cliente externo y mantener consistentes los productos que guardan el nombre de la categoría.

## Rutas implementadas

| Método | Ruta | Éxito |
| --- | --- | --- |
| `GET` | `/api/categories` | `200` + array |
| `GET` | `/api/categories/:id` | `200` + objeto / `404` |
| `POST` | `/api/categories` | `201` + objeto creado |
| `PUT` | `/api/categories/:id` | `200` + objeto actualizado |
| `DELETE` | `/api/categories/:id` | `200`, o `409` si está usada |

## Cambios realizados

1. `getCategories()` ahora incluye `id`; las vistas SSR siguen recibiendo los mismos campos anteriores.
2. `catalogService.js` centraliza búsquedas, CRUD, conteo y normalización de IDs.
3. Los nombres duplicados se detectan sin distinguir mayúsculas/minúsculas.
4. El renombrado actualiza `products.category` en una transacción SQLite.
5. La eliminación devuelve `409` cuando existen productos asociados.

## Rastro de código

```js
const update = db.transaction(() => {
    db.prepare(
        'UPDATE categories SET name = ?, icon = ?, type = ? WHERE id = ?'
    ).run(categoryData.name, categoryData.icon, categoryData.type, categoryId);

    if (current.name !== categoryData.name) {
        db.prepare('UPDATE products SET category = ? WHERE category = ?')
            .run(categoryData.name, current.name);
    }
});
```

## Validación realizada

Se usó una SQLite temporal y se verificó el flujo completo:

```json
{
  "created": 201,

```

## Criterios cumplidos

- CRUD completo en JSON.
- IDs y cuerpos inválidos controlados.
- Integridad de referencias textuales preservada al renombrar.
- Eliminación peligrosa bloqueada con un estado HTTP explícito.
